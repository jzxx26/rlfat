Module 1 • Foundations

RL learns a decision-making policy through interaction to maximise expected cumulative reward. Unlike supervised learning, the agent is not given correct actions; feedback may be delayed and actions affect future observations.

Agent
policy π → action a → Environment → state s′, reward r → Agent update

Elements

State describes the situation; action is a choice; reward is immediate feedback; policy maps states to action distributions; value predicts future return; model predicts next state and reward. A model is optional. Return Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + … . γ=0 values immediate rewards; γ near 1 values future rewards. Exploration gathers information; exploitation selects the best known action. Exploitation can still select an action with negative immediate reward if future return is better.

Tic-Tac-Toe (10-mark case)

Represent each board as a state, legal empty cells as actions. Give win reward +1, loss −1 and draw 0 (alternative conventions exist). Initialise nonterminal values, play games with exploratory moves, and update visited board values towards successor estimates. For example V(s)=0.4, V(s′)=0.8, α=0.1 gives V(s)←0.44 when reward is zero and γ=1. The greedy policy chooses the successor with greatest estimated winning utility. Self-play generates experience without labelled moves. Terminal reward is the actual outcome; value is a prediction of long-term outcome, not the immediate reward. Limitations: opponent changes, exploration, state explosion and reward design. Applications: games, robotics, scheduling, recommendations. Limitations of RL generally include sample cost, unsafe exploration, sparse rewards, instability, partial observability and transfer.

Module 2 • MDP, DP and Monte Carlo

Finite MDP

MDP = (S,A,P,R,γ). Markov property: conditional on current state and action, the distribution of next state and reward does not depend on earlier history. A policy π(a|s) is deterministic or stochastic. Episodic tasks terminate; continuing tasks need discounting or average reward. Prediction evaluates a policy; control improves it.

Bellman policy evaluation

For each state, average over actions and outcomes. Example: action A with probability 0.6 yields reward 2 and successor value 5; B with probability 0.4 yields reward 4 and successor value 10; γ=.8. V=0.6(2+.8×5)+.4(4+.8×10)=8.4. Repeat synchronous backups using only old values until change is below tolerance. DP needs a known model because it computes expectations over all possible transitions.

Policy iteration fully evaluates then improves; value iteration combines truncated evaluation with improvement. DP is polynomial in finite tabular representation but large state spaces and full sweeps are expensive; asynchronous DP and prioritised updates reduce unnecessary work.

Monte Carlo prediction and control

MC uses complete sampled returns, no model or bootstrap. First-visit averages returns after the first occurrence of a state in each episode; every-visit uses all occurrences. Compute returns backwards: G←r+γG. Example A →(+4) B →(−2) A →(+8) C →(+10) T, γ=.5. Returns from the four visits are 6.25,4.5,13,10 respectively. First-visit A=6.25; every-visit A=(6.25+13)/2=9.625. B=4.5. Incremental mean Q←Q+(G−Q)/N. Control estimates Q then improves an ε-soft policy; exploring starts or ε-greedy ensures coverage. Off-policy MC uses importance sampling ratios π(a|s)/b(a|s); products can have high variance.

Additional MC variations • importance sampling (friend’s p. 2)

ε-soft means π(a|s) ≥ ε/|A(s)| for every action. ε-greedy is a particular ε-soft policy: unique greedy action gets 1−ε+ε/k, others ε/k. Off-policy MC evaluates target policy π using trajectories generated by behaviour policy b. Coverage requires b(a|s)>0 wherever π(a|s)>0.

ρᵢ = ∏ over trajectory steps [π(a|s)/b(a|s)]
Ordinary IS: V = Σ ρᵢGᵢ / N
Weighted IS: V = Σ ρᵢGᵢ / Σ ρᵢ

Example: episode 1 has ratios .8/.4 and .5/.5, return 6; episode 2 has ratio .2/.4, return 10. Thus ρ₁=2, ρ₂=.5. Ordinary estimate=(12+5)/2=8.5; weighted estimate=17/2.5=6.8. Ordinary IS is unbiased under standard coverage assumptions but can have high variance; weighted IS is generally biased at finite sample sizes but consistent under suitable conditions. If total weight is zero, weighted estimate is undefined (often initialised to zero).

Incremental MC: after nth return, V ← V + (Gₙ−V)/n
Weighted incremental: C ← C+ρ; V ← V+(ρ/C)(G−V)

Example old V=4 after 3 returns, fourth return 8: new V=5. Weighted example old V=6, C=2, new ρ=.5, G=10: C=2.5, V=6+.5/2.5×4=6.8.

Module 3 • TD, control and planning

TD(0): δ=r+γV(s′)−V(s); V←V+αδ SARSA: δ=r+γQ(s′,a′)−Q(s,a) Q-learning: δ=r+γ maxₐ′Q(s′,a′)−Q(s,a) Both: Q←Q+αδ

TD learns online from sampled experience and bootstraps. SARSA is on-policy: choose a′ using behaviour policy and carry it into the next step. Q-learning is off-policy: behaviour may explore but target is greedy. Both initialise Q, choose action, observe transition, update and repeat. Under suitable tabular learning rates and exploration, Q-learning converges to Q*. SARSA can converge with greedy-in-the-limit exploration. TD has bootstrap bias but often lower variance than MC. MC waits for terminal; DP needs model.

Cliff walking: continued ε-greedy exploration makes the shortest path risky. SARSA accounts for exploratory future actions; Q-learning learns greedy optimal values, although actual behaviour may fall. Not a universal safety guarantee.

Models and Dyna-Q

Real transition → Q updateReal transition → Learn model → Simulated transitions → More Q updates

Model predicts next state and reward. Planning uses simulated experience; learning uses real experience. Dyna-Q performs real Q-learning update, stores transition in model, then samples n previously observed state-action pairs and updates Q from model predictions. Example real target=4+.9×10=13, Q=5, α=.1 →5.8; a simulated identical transition gives 6.52 if successor estimate unchanged. Benefits sample efficiency; costs computation and model bias. Dyna-Q+ adds exploration bonus for actions not tried recently.

Planning variants

Trajectory sampling focuses on states visited by simulated policy rather than uniformly sweeping all states. RTDP performs Bellman optimality backups along trials from relevant start states, avoiding irrelevant states. Planning at decision time searches from current state just before acting; background planning improves stored policy/value between decisions. Prioritised sweeping uses large Bellman errors to prioritise predecessors.

Module 4 • Approximate methods

Large/continuous states make tables infeasible. Approximate V or Q using features or neural networks; shared weights generalise across states. Objective for prediction is mean squared value error weighted by state visitation. Gradient MC uses full return; semi-gradient TD treats bootstrap target as fixed. Linear approximation has simple gradients; nonlinear approximation is expressive but can be unstable.

V̂(s,w)=wᵀx(s); Q̂(s,a,w)=wᵀx(s,a) w←w+α(target−prediction)∇w prediction For linear approximation ∇w prediction=x.

Module 5 • Applications and case studies

For a 10-mark case study: introduce problem, define state/action/reward, explain learning architecture and training, then benefits and limitations. The following are textbook-oriented explanations; illustrative MDP formulations are not claims about exact historical implementations.

TD-Gammon

Gerald Tesauro's backgammon program learned board evaluation using a neural network and temporal-difference learning from self-play. State encodes board positions and game information; actions are legal moves conditioned on dice; final outcome provides training signal. The network estimates expected game outcome. It evaluates candidate successor positions and selects promising moves. TD(λ) propagates prediction errors to recently visited states through eligibility traces: eₜ=γλeₜ₋₁+∇wV(sₜ); w←w+αδeₜ. Self-play continually generates opponents of comparable strength, removing the need for expert-labelled moves. Stochastic dice encourage diverse positions. Learned evaluation combined with search achieved strong play. Limitations: many games, domain representation, training cost, self-play may miss unusual opponent strategies.

Board + dice → Legal moves → Neural value estimates → Self-play → TD(λ) update

Samuel's Checkers Player

Arthur Samuel's pioneering checkers program combined game-tree search with learned evaluation of board positions. Rote learning stored previously evaluated positions; generalisation adjusted evaluation coefficients from experience and search-backed values. Features included material and positional properties. Minimax search estimated consequences of moves, and self-play supplied practice. Significance: early demonstration that a program could improve through experience instead of relying entirely on hand-coded rules. Limitations: hand-engineered features, limited compute, search depth and memory.

Watson's Daily-Double wagering

In Jeopardy!, the wager affects final winning probability, not merely expected score. State includes scores, remaining clues, game situation and estimated confidence of answering correctly; action is legal wager. Model possible correct/incorrect answers and future game outcomes, evaluate expected probability of winning, choose wager accordingly. Illustrative example: wager 1000 with probability .8 of correct gives expected score change .8×1000−.2×1000=600, but optimal wager may differ if preserving a lead is more valuable. This illustrates model-based decision making under uncertainty, simulation and a goal-oriented value function. Limitations: imperfect confidence calibration and opponent modelling.

Optimising memory control

Memory controllers schedule requests subject to DRAM timing constraints. State may include queue contents, bank/row status and recent requests; action selects an eligible command or request; reward reflects throughput or latency. RL learns a scheduling policy adapting to workload rather than relying solely on fixed heuristics. It can exploit row locality and parallel banks while balancing fairness. Challenges: enormous state space, strict timing constraints, changing workloads, real-time overhead and starvation prevention.

Human-level video game play (Atari DQN)

Input raw game frames, preprocess and stack recent frames to represent motion, feed into convolutional network producing Q-values for discrete actions. ε-greedy interaction fills replay buffer; random mini-batches train online network against target network. Rewards are game scores (often clipped in training). Same general algorithm learns across games without hand-crafted game-specific strategies. Benefits: end-to-end feature learning; limitations: large interaction cost, poor transfer, sparse reward and sensitivity to distribution shift.

Mastering Go (AlphaGo / AlphaZero distinction)

Go has huge branching factor, making exhaustive minimax impractical. AlphaGo combined policy networks to guide move selection, value networks to evaluate positions and MCTS to allocate search. Original AlphaGo used expert games and reinforcement learning through self-play; AlphaZero later learned from self-play without expert game data. MCTS uses policy priors and value predictions to focus search. Training improves policy from search decisions and value from final outcomes. Benefits: strategic planning and strong play; costs: computation and domain-specific simulator/rules.

Board → Policy prior + value → MCTS → Move → Self-play training

Personalised web services

State/context includes user history, session and candidate content; actions select recommendations or page variants; rewards can include clicks, engagement, satisfaction or long-term retention. Contextual bandits optimise immediate response; full RL handles sequential effects. Explore new items and exploit known preferences. Risks: feedback loops, privacy, popularity bias, reward hacking and delayed feedback. Offline evaluation and controlled experiments reduce deployment risk.

Robotics

State: sensor readings, pose and velocity; actions: torques, velocities or motor commands; reward: task completion, stability, energy and safety. Continuous control suits DDPG/SAC/PPO. Train in simulation, randomise dynamics and transfer to hardware; use constraints and safe fallback controllers. Benefits: adaptive control for manipulation, locomotion and navigation. Limitations: sample cost, sim-to-real gap, unsafe exploration, sensor noise and sparse rewards.

Module 6 • Deep RL

Deep learning basics

Neural layers compute z=Wx+b then nonlinear activation (ReLU=max(0,z), sigmoid or tanh). Forward pass produces predictions; loss measures error; backpropagation computes gradients by chain rule; gradient descent updates parameters. CNNs extract spatial features, recurrent networks can represent history in partially observed tasks. Deep RL combines neural representation with sequential decision objectives. Nonstationary targets and correlated samples make training harder than ordinary supervised learning.

DQN architecture and algorithm

Initialise online and target networks, collect ε-greedy transitions, sample random mini-batches, compute target using frozen target network, train online network, periodically copy weights. Replay reuses data and reduces correlation; target network reduces moving-target instability. DQN is off-policy and usually discrete-action. Limitations: overestimation, sample inefficiency, large action spaces and sensitivity to hyperparameters.

REINFORCE, A2C and A3C

REINFORCE uses complete Monte Carlo returns (see module 4). A2C uses synchronous parallel workers: each collects rollout, gradients/advantages are aggregated, then shared actor and critic update together. A3C uses asynchronous workers with local copies and asynchronous updates to shared parameters. Parallel environments diversify experience. A2C supports efficient batching and predictable updates; A3C reduces waiting but gradients can be stale. Neither requires standard DQN-style replay. Advantage can be n-step return minus value, or GAE: Aₜ=δₜ+γλδₜ₊₁+… . Example δ=[2,−1,3], γ=.9, λ=.8 gives A₀=2−.72+.72²×3=2.8352.

Model-based deep RL

Learn neural dynamics pθ(s′|s,a) and reward model from real transitions. Use model for simulated rollouts, planning (e.g. model predictive control) or policy training. MPC predicts several candidate action sequences, chooses best predicted return, executes first action and replans. Latent dynamics can compress high-dimensional observations. Advantages: sample efficiency and lookahead; limitations: model error compounds over long horizons, uncertainty and compute. Short rollouts, ensembles and real-data correction mitigate errors. Model-free DQN learns values directly without predicting environment transitions.

Module 7 • Advanced RL

DDPG

Off-policy deterministic actor-critic for continuous actions. Four networks: online actor μθ(s), online critic Qw(s,a), target actor and target critic. Replay stores transitions; behaviour adds exploration noise to deterministic actor. Critic learns Bellman target using target actor action; actor maximises critic estimate through chain rule. Soft-update both target networks. Useful for robotics; sensitive to hyperparameters, exploration noise and critic overestimation.

PPO

On-policy stochastic policy gradient method. Collect rollouts using old policy, estimate advantages (often GAE), optimise clipped surrogate over several mini-batch epochs, update value critic and refresh old policy. Clipping removes incentive for excessively large beneficial ratio changes; it is not a hard bound on policy probabilities or KL divergence. More stable than unconstrained policy gradients; less sample efficient than replay-based methods.

SAC

Off-policy stochastic actor-critic maximises reward plus entropy. Modern SAC uses stochastic actor, two critics and target critics, replay buffer and often automatic temperature tuning. Sample next action from actor; target uses minimum target critic and entropy term. Actor minimises entropy-adjusted negative Q. Temperature α controls exploration (not learning rate). Twin critics reduce overestimation. Benefits: robust exploration and sample efficiency; limitations: complexity, compute, temperature sensitivity.

Multi-agent RL (MARL)

Multiple agents interact in a shared environment. A Markov game extends MDP with joint action a=(a₁,…,aₙ), transition P(s′|s,a), and agent-specific rewards. Cooperative agents share goals; competitive agents have opposing goals; mixed games combine both. Independent Q-learning treats others as environment, causing nonstationarity as their policies change. Centralised training with decentralised execution (CTDE) uses global information during training but local observations at execution. MADDPG uses centralised critics conditioned on joint actions and individual actors; QMIX combines local Q-values monotonically for cooperative tasks. Challenges: credit assignment, partial observability, communication, scalability, equilibrium and nonstationarity. Example two robots coordinate delivery; shared reward encourages team success but makes individual contribution unclear. Difference from bandits: MARL involves strategic interactions and state transitions; bandits need not.

Multi-armed bandits

Choose among k arms with unknown reward distributions, maximise cumulative reward. No sequential state transitions in ordinary bandit. Contextual bandit observes context before choosing action. ε-greedy explores uniformly with probability ε; unique greedy arm probability 1−ε+ε/k. k=4, ε=.2 → .85 greedy, .05 each other. Sample-average update after nth observation Q←Q+(R−Q)/n. Old mean 6 over 4 pulls, fifth reward 11 →7. Constant α=.3 →7.5, useful for changing means. Optimistic initial values encourage early exploration; Thompson sampling draws reward-model parameters from posterior and chooses best sampled arm.

UCB(a)=Q(a)+c√(ln t/N(a)) UCB1=Q(a)+√(2 ln t/N(a)) Expected cumulative regret=Σ N(a)(μ*−μa)

Untried arms must be sampled initially or assigned infinite UCB. Use natural log. Regret uses true means, not estimated means, when given.

Inverse Reinforcement Learning (IRL)

Forward RL: known reward → learn policy. IRL: expert demonstrations → infer reward explaining behaviour → learn policy using inferred reward. Example autonomous driving: observe expert trajectories to infer preferences for safety, comfort and progress instead of manually specifying all weights. Assume reward Rw(s,a)=wᵀφ(s,a); estimate expert feature expectations; solve forward RL under current reward; compare learner and expert occupancy/feature expectations; update reward until behaviour matches. Maximum entropy IRL assigns higher probability to high-reward trajectories while accounting for multiple plausible behaviours: P(τ)∝exp(R(τ)). Reward ambiguity is fundamental: many reward functions explain same policy. Limitations: expert quality, expensive repeated planning, identifiability and distribution shift. Behaviour cloning directly learns actions from demonstrations; IRL learns underlying reward and can replan in changed environments.

RLHF

Reinforcement learning from human feedback uses preferences to align a policy when reward is difficult to specify. Typical language-model pipeline: pretrain model; supervised fine-tuning on demonstrations; collect pairwise human preferences over responses; train reward model; optimise policy using reward with KL penalty to reference model (often PPO). Preference model P(chosen≻rejected)=σ(Rchosen−Rrejected); loss=−ln P. Example reward scores 3 and 1: probability σ(2)=.8808, loss=.1269. KL penalty discourages excessive drift. Benefits: captures subjective quality and safety; limitations: expensive labels, bias, inconsistent preferences, reward hacking and overoptimisation. DPO is an alternative preference optimisation method without a separate online RL loop; not identical to PPO-based RLHF.

Pretrained model → SFT → Human preferences → Reward model → RL + KL penalty

DDPG critic uses gradient descent on batch MSE, exactly like DQN. General formula w←w−α∇L; do not assume a particular derivative unless the critic function is given. PPO advantage Aπ=Qπ−Vπ; one-step TD error is an estimate, not generally identical to the true advantage.

Combined critic loss = (y−Q₁)²+(y−Q₂)²

Quick self-test

Why does SARSA differ from Q-learning in cliff walking?Actual exploratory next action versus greedy target; SARSA accounts for risk under continued exploration.
Why do DQN replay and target networks help?Replay reduces correlation and reuses experience; frozen target stabilises regression targets.
What are MCTS's four stages?Selection, expansion, simulation, backpropagation.
What is the difference between IRL and RLHF?IRL infers reward from expert trajectories; RLHF typically learns preference reward from human judgments and optimises policy.
What makes SAC different from DDPG?Stochastic entropy-regularised policy, twin critics and exploration through entropy rather than added action noise.
